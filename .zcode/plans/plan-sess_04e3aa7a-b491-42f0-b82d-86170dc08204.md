# Gap-driven work extraction for bnh — including native→WASM replacement

## Problem
The loop assigns agents *failing tests* — symptom descriptions — and asks them to infer the feature behind them (`prompting.py:259`, `scheduler.py:19`). Models drown; only luna copes. Fix: translate scan evidence into **named capability gaps**, split into finite spec-first task cards that agents *build*, with failing tests demoted to acceptance criteria.

Per your direction, nothing is excluded as "impossible": the ~250 native/internet failures become their own gap classes — native code replaced by **WASM equivalents**, internet egress via the **proxy capability**.

## Part A — Gap layer (worklist for luna)

### A1. `src/browser_node_harness/surface.py` (~150 lines) — API surface probe & diff
- Generate one probe entry (CJS source): for each builtin in `module.builtinModules`, `require(m)` and record own keys + one level of prototype members for exported constructors; per-module load errors captured. Prints JSON to stdout.
- Run the identical probe via existing `TestRunner` against `config.oracle` (host Node) and `config.target` (browser runtime) with `TestCase(source_override=…)` — zero adapter changes.
- Diff → missing symbols per module (e.g. `async_hooks.executionAsyncResource`, 398 affected tests).

### A2. `src/browser_node_harness/gaps.py` (~300 lines) — gap formation & splitting
- Kinds and evidence:
  - `missing-api`: surface diff symbols confirmed by stderr (`X is not a function`, `Cannot read properties of undefined (reading 'X')`).
  - `missing-validation`: clusters with `ERR_INVALID_ARG_TYPE` / `ERR_MISSING_ARGS` / `ERR_OUT_OF_RANGE` per module (e.g. fs 198).
  - `native-addon-wasm`: tests with `scope` ∈ {`native_addon`, `native_api`} or sources requiring `…/binding.node`; evidence = **symbol histogram** from scanning the C/C++ addon sources in the Node checkout for `napi_*` / `node::*` / `v8::*` usage — the native analogue of the surface diff, decomposed by function family (values, strings, objects/properties, arrays/typed-arrays, functions/callbacks, promises, async-work, lifetimes/refinalize, error handling).
  - `host-network`: `internet` suite + timeout clusters over the proxy boundary.
- Affected tests: `tests.modules` join + `failure_fingerprint` clusters.
- Split into finite pieces: ≤8 symbols per missing-api card; one card per module for missing-validation; one card per napi/v8 function family; acceptance = ≤10 representative failing tests (smallest sources first) + total affected count. Rank by affected count.

### A3. DB + CLI
- `db.py`: `gaps` table (id, module, kind, symbols_json, affected_count, status `open|filled|closed`, evidence run_id), following the existing migration pattern.
- `cli.py`: `bnh gaps` (extract & store), `--list/--json`, `--emit <dir>` (task-card directories: `prompt.md` with spec-first framing — reference `lib/` source from the Node checkout, exact symbol list, acceptance tests, repro via `bnh test --worktree …` — plus `task.json` and copied sources), `--verify` (re-probe, mark filled).
- Dashboard: "Open gaps" panel in `dashboard.py`.

## Part B — Native→WASM enablement (drives the `native-addon-wasm` cards to green)

### B0. Toolchain bootstrap (itself the first emitted card)
- No Emscripten on this machine (clang exists). One-time `emsdk` install under `.bnh-state/toolchains/emsdk`, used host-side only — same trust posture as the existing Node/oracle binaries.
- Fallback if emsdk is rejected: distro clang `--target=wasm32 --no-standard-libraries` for freestanding N-API C addons (no libc); Emscripten is the default because addon sources are C++.

### B1. Host-side addon build pipeline (`src/browser_node_harness/addon_build.py` + daemon support)
- Detect `binding.gyp` dirs for failing native tests; compile addon sources to wasm32 (emcc) with a small `wasm_main` wrapper exporting `napi_register_module_v1`.
- Emit a manifest mapping expected `build/Release/*.node` paths → `.wasm` artifacts; `adapter-core.mjs` bundle collector includes artifacts via the existing read-binding; new `BNH_ADDON_MANIFEST` env plumbs it.

### B2. Runtime WASM N-API layer (`adapters/playwright/runtime/addon-napi.js`, new ~400 lines)
- `WebAssembly.instantiate` with an import table implementing `napi_*` over a JS-value handle table (create/get/set, strings, objects, arrays, typed arrays, function wraps, refs, finalize, env/instance data).
- Design constraints the cards must carry: typed-array/DataView wrappers into wasm memory must be invalidated on `memory.grow` (track detach); async work (`napi_create_async_work`) integrates with the existing timers/event-loop boundary; external buffers map to VFS-backed storage.
- `module-loader.js`: `.node` requires backed by a wasm artifact instantiate through this layer instead of `UnsupportedBrowserBoundaryError`.

### B3. Difficulty ordering (each phase gated on the previous)
1. `node-api` suite (~41 tests) — stable C ABI, cheapest entry.
2. `addons` suite (~54) — C++ node headers; symbol histogram scopes the port.
3. `js-native-api` (~55) — v8 C++ API subset via the same import machinery.
4. `internet` (~25) — not WASM: extend the existing `runtime/proxy.js` contract so net/http/dns egress flows through the host daemon when the proxy capability is enabled.
